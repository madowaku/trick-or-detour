# MVP v0.1 検証記録

検証日：2026-10-10。実装はTypeScript＋Vite、SVG＋DOM、固定60 tick/秒のシミュレーションです。

## 自動検証

`npm test`：30テスト。

- 決定後の進路が看板変更で変わらない。
- 同じ行き止まりの再訪で迷い値が増えず、記憶した道を避ける。
- 帰宅する子供が実際に入口まで来た経路を戻る。
- いたずらっ子による変更が後続にも残る。
- おやつ好きが看板よりお菓子を優先し、取得時に消える。普通の子は誘われない。
- 有限の配置数、入口と家へのお菓子禁止、入口隣接分岐へのおばけ禁止。
- おばけの迷い値、1.5秒停止、耐性到達後の帰宅と未到達時の1区間後退。
- おばけで押し戻された子供が既知の道を持っている場合も、無限往復や無限停止しない。
- 同時到着を登場ID順に処理し、入力の再生で同じイベント列になる。
- 0.6秒の看板操作間隔。ポーズ中の時間停止と入力禁止。
- 許容数を超えた到達で即時失敗。
- 無操作時と、全10ステージ×12系列のタイミングの異なる看板・アイテム操作でも、全員が最終的に帰宅または到達する。
- 新しいゲームによるリスタートで状態を初期化。
- 記録・設定の保存、ステージ解放、破損データと保存不可の場合の復旧。
- 全10ステージの、合法な操作間隔による星3つクリア手順。

`npm run build`：TypeScript検査とプロダクションビルド。

## ブラウザ検証

Codex In-app Browser（Chromium系）で以下を確認しました。

- タイトルから開始、ステージ1を実際にクリア、星3つの結果、次ステージへの移動。
- リロード後も星3つの記録とステージ2の解放が残る。
- ポーズ画面が出て、看板が無効化される。
- 準備画面から看板をタップし、Enterキーでも変更できる。
- お菓子はD1・D2・J2の指定ポイントに配置。おばけはJ2だけが候補。
- 配置後に残数が減り、配置表示が残る。
- リスタートで看板の向きとアイテム数が初期状態に戻る。
- 日本語・英語の切り替えとReduce motionの設定。
- ステージ10で3種類の子供といたずらの影響が描画される。
- コンソールにエラーなし。
- プロダクションビルドを `npm run preview` で開き、画像・フォント・ステージ開始・即時失敗・再挑戦・タイトル復帰を確認。こちらもコンソールエラーなし。

| 画面 | 結果 |
| --- | --- |
| 360×800 | 横スクロールなし、プレイ画面高さ800px内。看板約52×53px、下部操作ボタン高さ53px |
| 720×1280 | 横スクロールなし。看板約82×82px。配置・キーボード操作を確認 |
| 1360×900 | 左のステージ説明と右の盤面、HUD・操作ボタンを確認 |

後半ステージのUI確認は、開発専用の `tests/ui-fixture.html` で元の進行記録を退避して行い、検証終了後に復元しました。このページはプロダクションビルドに含まれません。
